# Chromnotes
[![Tests](https://github.com/rodrigodelbem/chromnotes/actions/workflows/ci.yml/badge.svg)](https://github.com/rodrigodelbem/chromnotes/actions/workflows/ci.yml)
![Coverage](https://img.shields.io/badge/coverage-66%25-yellowgreen)

Chromnotes turns every new browser tab into a focused note-taking surface. It pairs a rich block editor with fast search, tagging, theming so you can capture ideas the moment the tab opens.

## Highlights
- **New-tab notepad** – Loads instantly as your Chrome new tab override with zero distraction UI.
- **Editor.js-powered canvas** – Supports paragraphs, checklists, embeds, quotes, images, and raw HTML blocks; copies a clean plain-text snapshot for fast previews and search.
- **Organize effortlessly** – Categorize notes, filter by category, paginate long lists, and toggle dense/desktop layouts.
- **Smart autosave** – Persists edits automatically after a short pause and gently surfaces successful saves.
- **Themeable interface** – Pick from nine curated themes or flip light/dark via the header toggle; settings persist per user.
- **Portable data** – Export notes to `.txt`, import JSON/plain-text backups, and optionally sync with `chrome.storage.sync` when available (falls back to local storage).

## Tech Stack
- [Vite](https://vitejs.dev/) + TypeScript for the frontend build pipeline.
- [Editor.js](https://editorjs.io/) and companion tools for block editing.
- Jest (unit) and Cypress (end-to-end) test suites.
- Chrome Extension Manifest v3 with a new tab override.

## Getting Started

### Prerequisites
- Node.js 18+ (or a compatible runtime)
- npm 9+ (bundled with recent Node versions)

### Installation
```bash
npm install
```

### Local Development
```bash
npm run dev
```
The command starts the Vite dev server and opens Chromnotes at `http://localhost:5173`. The app runs as a standalone SPA; to preview in a new-tab context, build the extension and load it into Chrome (see below).

### Build
```bash
npm run build
```
Outputs the production bundle to `dist/` and copies the extension icon.

### Build the Chrome Extension
```bash
npm run build:extension
```
This command runs the production build, copies static assets (including `public/manifest.json` and `images/`), and validates that `manifest.json` exists in `dist/`.

#### Load in Chrome
1. Open `chrome://extensions/`.
2. Enable **Developer mode**.
3. Choose **Load unpacked** and select the `dist/` folder.
4. Open a new tab to test Chromnotes.

### Testing & Quality
- **Unit tests:** `npm test`
- **End-to-end tests (headless):** `npm run test:e2e`
- **Open Cypress runner:** `npm run cy:open`
- **Lint:** `npm run lint`
- **Format (Prettier):** `npm run format`
- **Format check:** `npm run format:check`

## Project Structure
- `src/` – Application sources (state management, Editor.js bindings, modal/view logic, styles).
- `scripts/` – Custom Node scripts (`build-extension.mjs`, `post-build.mjs`).
- `public/` – Chrome extension manifest and static assets copied during extension builds.
- `cypress/` & `src/__tests__/` – Automated test suites.
- `dist/` – Generated at build time; ignored from source control.

## Data & Sync Behavior
- Notes, settings, and layout preferences live in `chrome.storage.sync` when available and enabled; otherwise the app uses `chrome.storage.local`.
- A localStorage snapshot (`chromnotes_state`) mirrors the latest saved state as a safety net.
- Import expects JSON generated by Chromnotes or plain text (`.txt`); export produces a newline-delimited plain-text archive.
